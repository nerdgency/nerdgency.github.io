# Workflows

A **workflow** is something that happens after a submission. Each form has its own, on its **Workflows** tab. A workflow has:

| Setting | |
| --- | --- |
| **Name** | For you. Shown in the log. |
| **Enabled** | A switched-off workflow does not run. |
| **Event** | **Submission Created**, **Submission Updated** (an edit from the control panel, or a visitor editing through `submission_handle=`), or **Submission Created or Updated**. |
| **Action** | **Send an email**, **Call a webhook** or **Send to a connection**. |
| **Conditions** | Optional. The workflow runs only when they hold for the submitted answers, using the same [condition builder](./conditions.md) as fields. |

Workflows receive every answer, including real file ids for uploads, even when the form does not store submissions or their data. A form with storage turned off is a **workflows only** form.

## Send an email

| Setting | |
| --- | --- |
| **Recipients** | Any number of rows, each delivered as **To**, **Cc** or **Bcc**: a typed address, a member, every member of a role, or a **form field**. |
| **From name**, **From email**, **Reply-to**, **Subject** | A blank From uses the site's webmaster name and address, and a blank Subject uses the form's name. The subject can include answers with `{field:HANDLE}`. Reply-to is a fixed address, and is left off when blank. |
| **Message** | One of the [email theme's](./themes.mdx#email-themes) messages, such as **Submission**, which lists every answer, or text written on the workflow. |
| **Use the email layout** | Wrap the message in the email theme's `_layout`. |
| **Attach uploaded files** | Attach the files uploaded with the submission. |
| **Attachments** | Files from ExpressionEngine's file manager to attach to every email this workflow sends, such as a brochure. |

A **form field** recipient only sends to an address the field can safely resolve to. Otherwise anyone who submits the form could make your site email any address. The field must be one of:

- an option field whose choices come from **Recipients**, where each choice has addresses that never reach the page;
- an option field whose choices are **Members**;
- a field with **Allow as Workflow Recipient** turned on, such as a "send me a copy" email field. Turn that on only where you mean it.

See [Email notifications](/docs/formidable/guides/email-notifications) for a worked example.

## Call a webhook

Posts the submission as JSON to a URL.

| Setting | |
| --- | --- |
| **URL** | Where to post. |
| **Secret** | Optional. When set, each request carries an `X-Formidable-Signature` header: the HMAC-SHA256 of the request body, keyed with the secret. |
| **What to send** | Any of: the form (id, handle, name), the submission (id, status, member id, date), the answers, and the member who submitted. The event name is always sent. |
| **Member details** | Which member fields to include, when the member is sent: username, screen name, email address, primary role, join date, and custom member fields. |
| **Leave out of the answers** | Answers not to send, such as anything sensitive the receiving service does not need. |

To check a signature, compute the HMAC of the raw request body with your secret and compare it with the header in constant time:

```php title="webhook-receiver.php"
<?php
$body = file_get_contents('php://input');
$expected = hash_hmac('sha256', $body, getenv('FORMIDABLE_WEBHOOK_SECRET'));
$given = $_SERVER['HTTP_X_FORMIDABLE_SIGNATURE'] ?? '';

if (! hash_equals($expected, $given)) {
    http_response_code(401);
    exit;
}

$payload = json_decode($body, true);
// $payload['event'] is always present; the rest depends on "What to send".
```

## Send to a connection

Pushes the submission to a third-party service through a saved [connection](./connections.md): a mailing list or a CRM.

| Setting | |
| --- | --- |
| **Connection** | Which saved connection to use. |
| **Target** | The list, audience or object at the provider, where the provider needs one. |
| **Mapping** | Which form field fills which of the provider's fields. |

Map form fields to `email`, `name`, `first_name`, `last_name`, `phone` and `company`, and each provider translates them into its own field names, so one mapping works with any provider. Any other key is sent as that provider's own custom field, named exactly as the provider knows it.

## The workflow log

Every workflow run is recorded on **Formidable › Workflow Log**. A form's **Workflows** tab switches between **Simple**, **Detailed** and **Recent runs**: its latest runs, each with its result, action, time, duration and message, filterable by result, with a link to the full log. The tab is marked with a red dot when a workflow's most recent run failed. Each submission's page has the same three views, read-only, opening on that submission's runs.

| A run records | |
| --- | --- |
| **Result** | **Succeeded**, **Failed** (the mail server, API or URL refused), or **Nothing to do** (it ran, but there was no recipient, no URL or no mapped field). |
| **Conditions** | The workflow's conditions at the time, each marked as held or not for the answers given. |
| **Answers** | The values the conditions were checked against. |
| **What was sent** | Email: recipients, from, reply-to, subject, attachments and the plain-text body. Webhook: the URL, whether it was signed, the body, and the response. Connection: the mapped payload and the provider's request and response. Credentials are never recorded. |

Run data is visitor data, so it is **encrypted at rest**.

**Run again** replays a run through the workflow **as it is configured now**, with the answers the original run was given. Correct a mapping or a recipient, then run it again. Conditions are not checked, because the person pressing the button decided it should run. The new run records which run it replayed and who pressed the button. It sends real email and calls real services.

The log needs the **View workflow log** permission. **Run again** also needs **Manage forms**. Runs older than 30 days are pruned as new ones are written. Change that, or turn the log off, in `config.php`:

```php title="system/user/config/config.php"
$config['formidable_workflow_log_days'] = 90; // 0 keeps every run
$config['formidable_workflow_log'] = 'n';     // record nothing
```

A failure to write the log never fails the visitor's submission. It goes to ExpressionEngine's developer log instead.

## For developers

The [`formidable_submission_complete`](/docs/formidable/developer/hooks) hook fires after a submission is stored and before workflows run.
